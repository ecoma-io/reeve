# Gap matrix

_What the suite does not prove, prioritised, with the executable evidence that would close each row. Every claim is grounded in `file:line` and was checked against the source on this branch; where a claim is an inference it says INFERRED. Companion to `test-architecture.md`, which is the descriptive half. Nothing here is a request to change production code — a defect found is recorded, not fixed._

**Quality outranks the number.** Root's standing instruction for this round: the success criterion is "every covered branch has an assertion that would fail on a real regression", not "90% was reached". A branch that can only be covered by a test which does not genuinely protect behaviour should be left uncovered and classified — see "Branch-coverage debt" below. Coverage bought with assertion-free tests, over-mocking, or trivial-accessor tests is a defect in this round, because it converts a visible gap into an invisible one.

Priorities: **P0** architectural or security correctness — authority, model orchestration and fallback, dry-run, idempotency, configuration validation, evidence verification. **P1** important behaviour. **P2** ordinary edge cases. **P3** low value.

Owner TL is the lead whose files the fix lands in: **TL2** duty/provider/fallback, **TL3** authority/config/state and `src/doctor/**`, **TL4** GitHub/integration/adversarial and `src/duties/review/**`, **TL5** coverage/mutation/CI infrastructure.

## Method note

The brief specified Grand Subagents via the Agent tool. **No `Agent` / `Task` tool exists in this environment** — the tool surface offers only `TaskStop` and cross-session `SendMessage`, and `mcp__Claude_Code_Remote__create_session` spawns sessions in other containers that cannot read this worktree. The roster was therefore run as sequential, independently-scoped analysis passes over disjoint file lists (source inventory → test inventory → cross-index → intent-matrix citation audit → adversarial re-read of the draft), with the adversarial pass re-deriving every P0 claim from the source rather than from the draft. Rows `G-01`, `G-03`, `G-12`, `G-13`, `G-14`, `P-08`, `P-13`, `P-14`, `Q-14` and the `intent-matrix.md` GAP-4 finding were produced by that adversarial pass rather than by the first draft, and `Q-05` was **corrected** by it: the draft reasoned from test-file size that its branches were "probably reached", and a targeted coverage run showed every one of them uncovered. That correction is the argument for the whole method — coverage is measured, never inferred, and a large test file is not evidence about any particular branch.
